Security and compliance teams deal with a constant stream of documents that need the same first question answered: *what kind of sensitive thing is this, and how urgently does it need attention?* A leaked API key, a phishing attempt, a customer's medical record pasted somewhere it shouldn't be — these all look like "a block of text" to a naive system, but they need completely different handling. ThreatLens is a classifier built to make that first call automatically.

<Callout type="info" title="The task">
  Seven categories: credentials, PII, financial, medical, confidential, malicious, and safe. The goal isn't just "is this sensitive" — it's which *kind* of sensitive, since that determines who gets paged and how fast.
</Callout>

## Starting with class imbalance, not a model

The raw labelled data wasn't close to balanced — the malicious category had substantially more examples than medical, which would have quietly taught any model to favor the bigger classes. I sampled 1,300 documents per category for a balanced set of 9,100 documents before training anything, specifically so the eventual accuracy numbers would mean what they claim to mean, rather than reflecting which class happened to be biggest in the raw data.

Split 7,280 / 910 / 910 for train, validation, and test — stratified so all seven categories stayed represented in equal proportion across every split.

## Baseline first, transformer second

The same pattern as everywhere else I've done this: build the honest classical baseline before reaching for a transformer, so the eventual improvement number is measuring something real.

```python
VALID_CATEGORIES = {
    "credentials", "pii", "financial", "medical",
    "confidential", "malicious", "safe",
}
```

| Model | Accuracy | Macro F1 |
|---|---|---|
| TF-IDF + Logistic Regression | 98.02% | 98.02% |
| Fine-tuned RoBERTa | **98.35%** | **98.37%** |

<Callout type="tip" title="When a strong baseline is a good sign, not a bad one">
  A 98% baseline isn't a weak strawman — it means the categories are genuinely well-separated in the text, which is exactly what you'd want for a production classifier. RoBERTa's edge over it is real but modest, and that's the honest result, not an inflated one.
</Callout>

RoBERTa's gains were concentrated in exactly the categories you'd expect to be hardest: **confidential** (precision rose from 95.38% to 93.33% but recall climbed from 95.38% to 96.92%) and **safe** — the one category defined mostly by the *absence* of a signal rather than the presence of one, which is the category classical bag-of-words features tend to find the hardest to pin down.

<Divider />

## Reading the mistakes, not just the score

98.35% accuracy on a 910-document test set means roughly 15 documents got misclassified. I pulled every one of them and read the actual text rather than treating "15 errors" as a number to report and move past.

```python
error_analysis["confidence"] = (
    roberta_test_probabilities.max(axis=1).astype(np.float32)
)
```

The confusion pairs clustered exactly where a human would expect difficulty: **confidential** and **safe** sitting closest together in the model's decision space, since the line between "internal but harmless" and "internal and sensitive" genuinely depends on context a single paragraph doesn't always carry. That's not a modelling failure — it's the actual ambiguity in the task showing up honestly in the error analysis, which is more useful than a clean number with no visibility into where it breaks.

A quick inference check makes the practical behavior concrete:

```python
Input: "A deployment guide contains only example placeholders
        such as API_KEY=xxxxxxxx and no working secret."
Prediction: safe          Confidence: 99.84%

Input: "A message asks the recipient to open an urgent sign-in
        page and enter their corporate username and password."
Prediction: malicious      Confidence: 99.87%
```

## What I'd tell someone starting this today

Balancing the dataset before touching a model mattered as much as the architecture choice. And the baseline wasn't a formality to beat — a strong classical baseline is a genuine signal that the problem is well-posed, and the honest comparison (not an inflated one) is what makes the final 98.37% Macro F1 mean something. The error analysis mattered more than the headline number: knowing *which* two categories a model confuses, and *why*, is what actually tells you whether it's safe to deploy.
